Gestión de Software Aprobado

Código: MC134-IT-1
Última revisión: 2/12/2025
Rev. N°: 1
Cumple: TISAX (VDA ISA 1.3.4), ISO 27001:2022 (A.8.19, A.8.8, A.5.9, A.8.32, A.5.32)

1 OBJETIVO

Garantizar que en PRODISMO SRL solo se utilice software evaluado y aprobado para el procesamiento de los activos de información, determinando los tipos de software gestionados (firmware, sistemas operativos, aplicaciones, bibliotecas y controladores), manteniendo repositorios de software gestionado protegidos contra manipulaciones no autorizadas, conociendo las versiones y niveles de parche del software en uso y revisando periódicamente su aprobación. Esta política da cumplimiento al control 1.3.4 del catálogo VDA ISA 6 del marco TISAX y al control A.8.19 (Instalación de software en sistemas operacionales) del Anexo A de ISO/IEC 27001:2022, complementado por los controles A.8.8, A.5.9, A.8.32 y A.5.32.

2 ALCANCE

Esta política aplica a:

  • Todo el software instalado o ejecutado en activos de PRODISMO SRL o utilizado para procesar su información y la de sus clientes, incluyendo:
    • Estaciones de trabajo y servidores: sistemas operativos, aplicaciones de oficina, software CAD/CAM/CAE (CATIA, NX, AutoForm, Cad-Cam), cliente del ERP SIP / SIP4.0, AnyDesk y herramientas de seguridad.
    • Equipos de red, cámaras de vigilancia y hardware: firmware y BIOS/UEFI.
    • Equipos de planta: firmware y software de controladores CNC, PLC y robots de las líneas de ensamble.
    • Software desarrollado por terceros: ERP SIP / SIP4.0 (Enter-Geminus) y aplicación web viajes.prodismo.com (Cubits S.R.L.), incluidas sus bibliotecas y componentes.
  • Todos los empleados, contratistas y proveedores que soliciten, instalen, actualicen o utilicen software en activos de PRODISMO SRL.

Los servicios en la nube (SaaS) se evalúan según la política MC133-IT-1; esta política alcanza el software que dichos servicios requieran instalar en los equipos de PRODISMO SRL.

4 DEFINICIONES

Software gestionado:

Software cuyo uso, versión, origen y actualización están bajo control de IT y registrados en el inventario F134-IT-1.

Software aprobado:

Software evaluado según el procedimiento P134-IT-1 y autorizado por el IT Manager para su uso en PRODISMO SRL.

Firmware:

Software embebido en un dispositivo de hardware (equipos de red, cámaras, BIOS/UEFI, controladores CNC, PLC, robots).

Sistema operativo:

Software base que gestiona el hardware de un equipo (por ejemplo, Windows y Windows Server).

Aplicación:

Software que ejecutan los usuarios para realizar tareas (por ejemplo, Microsoft 365, CATIA, NX, cliente SIP4.0).

Biblioteca o componente:

Software reutilizable del que dependen otras aplicaciones (frameworks, runtimes como .NET o Visual C++ Redistributable).

Controlador (driver):

Software que permite al sistema operativo comunicarse con un dispositivo (placas de video, impresoras, periféricos).

Repositorio de software gestionado:

Ubicación controlada desde la que se obtiene e instala el software aprobado.

Nivel de parche:

Versión y actualizaciones de seguridad aplicadas a un software.

Fin de soporte (EOL):

Fecha a partir de la cual el fabricante deja de publicar actualizaciones de seguridad para un software.

Software no autorizado:

Software no incluido en el inventario de software aprobado.

5 RESPONSABLES

Alta Dirección

  • Aprobar esta política y asignar los recursos para licencias, herramientas y actualizaciones.
  • Aprobar las excepciones por software sin soporte con riesgo Alto.

IT Manager / Responsable de Seguridad de la Información (RSI)

  • Aprobar o rechazar el software solicitado y mantener el inventario F134-IT-1.
  • Realizar la revisión periódica de la aprobación y definir los plazos de aplicación de parches.
  • Aprobar las excepciones de bajo riesgo y escalar las de riesgo Alto.

Administrador de IT

  • Instalar el software aprobado, únicamente desde los repositorios gestionados.
  • Mantener y proteger los repositorios, y registrar versiones y niveles de parche.
  • Aplicar las actualizaciones y detectar software no autorizado.

Responsables de Datos y de Área

  • Solicitar el software que necesita su área y validar su necesidad (por ejemplo, CATIA, NX, AutoForm y Cad-Cam en Ingeniería).
  • Participar en las pruebas de nuevas versiones del software de su área.

Mantenimiento / Producción

  • Coordinar con fabricantes e integradores la actualización del firmware y software de equipos de planta (responsable: --TODO--).
  • Definir las ventanas de mantenimiento para actualizaciones en la planta.

Proveedores

  • Entregar versiones con notas de versión y origen verificable (Enter-Geminus, Cubits S.R.L., Armanet S.A., fabricantes de equipos).
  • Informar vulnerabilidades y actualizaciones de seguridad de su software (según MC124-IT-1).

Usuarios

  • Utilizar solo software aprobado y no instalar, descargar ni ejecutar software por su cuenta.
  • Reportar software sospechoso o no autorizado a IT.

7 SOFTWARE APROBADO

  • Solo se instala y utiliza software aprobado y registrado en el F134-IT-1, incluido el software gratuito, de prueba o de código abierto.
  • La instalación la realiza únicamente IT; los usuarios no tienen privilegios de administrador en sus equipos (situación actual y plan de adecuación: --TODO--).
  • Antes de aprobar un software se evalúa, según P134-IT-1: necesidad, origen oficial, licencia válida (Ley 11.723), soporte vigente del fabricante, vulnerabilidades conocidas, compatibilidad y acceso a datos o a la red.
  • Si el software requiere un servicio en la nube o envía información a terceros, se evalúa además según MC133-IT-1.
  • Está prohibido utilizar software sin licencia, de fuentes no oficiales, sin soporte del fabricante (salvo excepción aprobada) o instalado desde cuentas o medios personales.

8.2. Protección contra Manipulaciones No Autorizadas

  • Solo los administradores de IT, con cuentas nominativas y MFA, pueden escribir en el repositorio de instaladores; el resto de los usuarios no tiene acceso o tiene solo lectura.
  • El software se descarga únicamente de fuentes oficiales; se verifica la firma digital del fabricante o el valor hash (SHA-256) antes de guardarlo, y se registra en el F134-IT-1.
  • Todo instalador se analiza con el antivirus antes de incorporarlo al repositorio.
  • El repositorio se respalda periódicamente y sus accesos y cambios quedan registrados.
  • El acceso de proveedores a los repositorios de software de terceros se controla según MC124-IT-1.

9 VERSIONES Y NIVELES DE PARCHE

  • El F134-IT-1 registra, para cada software aprobado, la versión aprobada, el nivel de parche, la fecha de fin de soporte y los equipos donde se usa.
  • Las actualizaciones de Windows, Windows Server y Microsoft 365 se aplican en un ciclo mensual.
  • Plazos para vulnerabilidades: Crítica, hasta 7 días; Alta, hasta 30 días; Media y Baja, en el siguiente ciclo mensual.
  • El firmware se revisa al menos semestralmente; en equipos de planta, la actualización se realiza en ventanas de mantenimiento coordinadas con Producción.
  • El software que llega a su fin de soporte se reemplaza o actualiza; si no es posible (por ejemplo, controladores de máquinas con sistemas antiguos), se aprueba una excepción con controles compensatorios, como el aislamiento de red (F124-IT-3).

10 REVISIÓN PERIÓDICA DE LA APROBACIÓN

  • La aprobación de cada software se revisa una vez al año, verificando que siga siendo necesario, tenga licencia y soporte vigentes y no presente vulnerabilidades sin tratar.
  • Además, se revisa ante: fin de soporte, vulnerabilidades críticas, vencimiento de licencias o cambio de proveedor.
  • El software cuya aprobación se retira se desinstala de todos los equipos y se marca como Retirado en el F134-IT-1.

11 DETECCIÓN DE SOFTWARE NO AUTORIZADO

  • IT compara trimestralmente el software instalado en los equipos con el inventario de software aprobado (herramienta: --TODO--).
  • El software no autorizado se desinstala; si es malicioso o produjo un incidente, se gestiona según P121-IT-1.
  • Los casos detectados se informan al Comité de Seguridad de la Información.

12 CAMBIOS Y NUEVAS VERSIONES DE SOFTWARE DE TERCEROS

  • Las nuevas versiones del ERP SIP / SIP4.0 y de viajes.prodismo.com se prueban y aprueban antes del pase a producción, por una persona distinta de quien las desarrolla (segregación de funciones, MC122-IT-1).
  • Cada versión aprobada se registra en el F134-IT-1 con sus notas de versión y se conserva la versión anterior para poder volver atrás.
  • Los cambios de software en el marco de proyectos se gestionan además según MC123-IT-1.

13 COMUNICACIÓN Y CONCIENTIZACIÓN

  • Esta política y la lista de software aprobado se publican en la intranet.
  • Las campañas anuales de concientización incluyen los riesgos de instalar software no autorizado.

14 REGISTROS Y EVIDENCIAS

14.1. Registros Obligatorios

  • F134-IT-1: Inventario de Software Aprobado (incluye repositorios).
  • F134-IT-2: Solicitud y Evaluación de Software Nuevo.
  • Registros de aplicación de parches y de revisiones anuales de aprobación.
  • Informes trimestrales de detección de software no autorizado.
  • Excepciones aprobadas por software sin soporte.

14.2. Retención de Registros

  • Inventario de software aprobado: versión vigente y versiones de los últimos 3 años.
  • Solicitudes, evaluaciones y excepciones: 3 años.
  • Registros de parches y detección de software no autorizado: 1 año.

15 MONITOREO Y CUMPLIMIENTO

  • Auditorías internas anuales sobre una muestra de equipos.
  • Indicadores de desempeño:
    • Software instalado que figura en el inventario aprobado: Objetivo 100%.
    • Equipos con el ciclo mensual de parches aplicado: Objetivo > 95%.
    • Vulnerabilidades críticas corregidas en plazo: Objetivo > 95%.
    • Software aprobado con versión y nivel de parche registrados: Objetivo 100%.
    • Revisiones anuales de aprobación realizadas en plazo: Objetivo 100%.

16 SANCIONES POR INCUMPLIMIENTO

El incumplimiento de esta política podrá dar lugar a acciones disciplinarias de acuerdo con la política de sanciones de la empresa, que pueden incluir desde amonestaciones hasta la desvinculación laboral, dependiendo de la gravedad de la infracción. En el caso de proveedores, podrá implicar la rescisión del contrato y las acciones legales que correspondan.

17 REVISIÓN Y ACTUALIZACIÓN

  • Revisión anual de esta política, del procedimiento P134-IT-1 y del inventario de software aprobado.
  • Actualización inmediata ante cambios tecnológicos significativos o nuevas amenazas.
  • Responsable de la revisión: RSI en coordinación con el IT Manager.
