Procedimiento de Gestión de Riesgos de Seguridad de la Información

Código: P141-IT-1
Última revisión: 15/01/2026
Rev. N°: 1
Cumple: TISAX AL3, ISO 27001:2022

1 OBJETIVO

Implementar un proceso ágil y efectivo para identificar, evaluar y mitigar riesgos, enfocado en activos críticos (ej.: CATIA, SIP/SIP4.0) en cumplimiento de ISO/IEC 27001:2022, así como los requisitos del marco TISAX y cumplimiento de requisitos de clientes automotrices.

2 EVALUACIÓN DE RIESGOS

Metodología:

Basada en ISO 27005 y VDA ISA, adaptada a entornos on-premise.

Pasos:

  1. Identificación de Activos y Amenazas:
    • Activos Críticos: CATIA (🔴), SIP (🔴), Windows Server (🟡).
    • Amenazas Comunes:
      • Ransomware en servidores de diseño.
      • Acceso no autorizado a SIP por phishing.
  2. Evaluación de Probabilidad e Impacto:
    • Escala 1-5 (1=Bajo, 5=Crítico).
    • Ejemplo:
    Riesgo Probabilidad Impacto Nivel de Riesgo
    Ataque ransomware a servidores Internos 2 4 Medio (8) 🟡
    Fuga de datos de SIP/SIP4.0 por phishing a empleados 2 4 Medio (8) 🟡
  3. Documentación:
    • Registro de Riesgos (Plantilla):
    ID Riesgo Activo Afectado Clasificación Responsable Controles Existentes Acciones de Mitigación
    R1-IT-01 Ataque ransomware a servidores Internos Servidor On-Premise Medio (8) 🟡 Admin IT
    1. Backups diarios.
    2. Firewall perimetral.
    3. VPN obligatoria para accesos remotos.
    4. Backup en almacenamiento externo al final de cada proyecto.
    1. Segmentar red VLAN para ingeniería.
    2. Simulacro de ataque Semestral.

3 GESTIÓN DE RIESGOS

Matriz de Tratamiento:

Riesgo Estrategia Acciones Específicas Plazo
Ataque ransomware a servidores Internos Mitigar
  • Implementar segmentación VLAN para ingeniería.
  • Simulacro de ataque Semestral.
  • Cifrado.
 90 días
Fuga de datos de SIP/SIP4.0 por phishing a empleados Mitigar
  • Capacitación anti-phishing mensual.
  • Monitoreo con SIEM.
 60 días

Responsables:

  • Dueño del Riesgo: Asignado según área (ej.: Admin IT para riesgos de infraestructura).
  • IT Manager: Supervisa la implementación de controles.

4 REVISIONES PERIÓDICAS

Frecuencia:

  • Trimestral: Riesgos 🔴 Críticos.
  • Semestral: Riesgos 🟠 Altos/🔵 Medios.
  • Ad-hoc: Tras incidentes o cambios (ej.: nuevo cliente con requisitos adicionales).

Checklist de Revisión:

  • ¿Los controles mitigaron el riesgo? (Verificar con métricas).
  • ¿Cambió la probabilidad/impacto? (Actualizar matriz).
  • ¿Se asignaron nuevos responsables?

5 COMUNICACIÓN Y MONITOREO

Herramientas:

  • Dashboard de Riesgos: Power BI o Excel con:
    • Nivel de riesgo actualizado.
    • Estado de acciones de mitigación.
  • Alertas Automáticas: Integrar SIEM (ej.: detección de intentos de acceso fuera de horario).

Ejemplo Práctico

Caso: Nuevo requisito de BMW para watermarking en archivos de diseños CATIA

  1. Identificar Riesgo: "Fuga de diseños sin watermarking" → Impacto: 5 (Crítico).
  2. Mitigación:
    • Instalar módulo de watermarking en CATIA.
    • Capacitar a ingenieros/diseñadores.
  3. Responsable: Responsable de Datos.

Recomendaciones

  • Automatización: Usar Microsoft Defender for Endpoint para detección de ransomware.
  • Integración con TISAX: Vincular riesgos a la F121-IT-1 Declaración de Aplicabilidad (DoA).
  • Ejemplo de Clientes Automotrices:
    • VW: Enfocarse en protección física de servidores on-premise.
    • BMW: Priorizar watermarking y logs detallados.
