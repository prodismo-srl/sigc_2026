Procedimiento de Gestión de Software Aprobado

Código: P134-IT-1
Última revisión: 2/12/2025
Rev. N°: 1
Cumple: TISAX (VDA ISA 1.3.4), ISO 27001:2022 (A.8.19)

1 OBJETIVO

Describir las actividades para que en PRODISMO SRL solo se utilice software evaluado y aprobado: solicitud, evaluación, aprobación, incorporación a repositorios protegidos, instalación, actualización y control de versiones y parches, revisión periódica de la aprobación y detección de software no autorizado, en cumplimiento de la política MC134-IT-1, del control 1.3.4 del catálogo VDA ISA 6 (TISAX) y del control A.8.19 de ISO/IEC 27001:2022.

2 ALCANCE

Este procedimiento aplica a:

  • Todo el software gestionado: firmware, sistemas operativos, aplicaciones, software de terceros a medida, bibliotecas y controladores.
  • Todos los equipos de PRODISMO SRL: estaciones de trabajo, servidores, equipos de red, cámaras y equipos de planta.
  • Todas las personas que soliciten, instalen o actualicen software, incluidos los proveedores.

4 DEFINICIONES

Se aplican las definiciones de la política MC134-IT-1. En particular:

Software aprobado:

Software evaluado según este procedimiento y registrado en el F134-IT-1.

Repositorio de software gestionado:

Ubicación controlada desde la que se obtiene e instala el software aprobado.

Valor hash (SHA-256):

Huella digital de un archivo que permite comprobar que no fue modificado.

Fin de soporte (EOL):

Fecha a partir de la cual el fabricante deja de publicar actualizaciones de seguridad.

6 DESCRIPCIÓN DEL PROCEDIMIENTO

6.1. Etapa 1 – Solicitud

  • El solicitante completa el F134-IT-2 (hoja "Solicitud") y lo envía a itprodismo@prodismo.com, indicando software, fabricante, versión, finalidad, equipos, licencia y si procesará información de clientes o datos personales.
  • IT verifica primero si existe un software aprobado equivalente en el F134-IT-1; si existe, se ofrece ese.

6.2. Etapa 2 – Evaluación

El IT Manager evalúa el software con el checklist del F134-IT-2:

Criterio Qué se verifica
Necesidad Uso justificado para el trabajo y sin alternativa aprobada.
Origen Descarga desde el sitio oficial del fabricante o proveedor autorizado.
Licencia Licencia válida para uso comercial (Ley 11.723).
Soporte Versión con soporte vigente y actualizaciones de seguridad.
Vulnerabilidades Sin vulnerabilidades críticas conocidas sin parche.
Integridad Instalador firmado digitalmente o con hash verificado.
Datos y conexiones Si procesa datos de clientes o se conecta a servicios externos, cumple MC133-IT-1.
Compatibilidad y privilegios Compatible con los equipos; funciona sin privilegios de administrador del usuario.
  • El software es aprobable si cumple todos los criterios obligatorios del checklist.

6.3. Etapa 3 – Aprobación y Registro

  • El IT Manager registra la decisión en el F134-IT-2: aprobado, aprobado con condiciones o rechazado.
  • Si se aprueba, el software se da de alta en el F134-IT-1 con versión, tipo, licencia, repositorio, responsable, fin de soporte y fecha de próxima revisión.

6.4. Etapa 4 – Incorporación al Repositorio

  • El Administrador de IT descarga el instalador solo desde la fuente oficial.
  • Verifica la firma digital o el hash SHA-256 publicado por el fabricante y lo analiza con el antivirus.
  • Guarda el instalador en el repositorio de instaladores de IT (--TODO-- ubicación) y registra el hash en el F134-IT-1.

6.5. Etapa 5 – Instalación

  • La instalación la realiza únicamente IT, desde el repositorio gestionado o desde la fuente oficial registrada.
  • Se registran los equipos donde se instala el software.

6.6. Etapa 6 – Actualizaciones y Parches

  • Se aplican las actualizaciones según las frecuencias y plazos de la sección 7.
  • Después de cada actualización se actualiza la versión y el nivel de parche en el F134-IT-1.
  • Las nuevas versiones de software de terceros se gestionan según la sección 9.

6.7. Etapa 7 – Revisión Anual y Retiro

  • El IT Manager revisa anualmente cada software del F134-IT-1: necesidad, licencia, soporte y vulnerabilidades.
  • También se revisa ante fin de soporte, vulnerabilidades críticas o vencimiento de licencias.
  • Si se retira la aprobación, IT desinstala el software y lo marca como Retirado.

6.8. Etapa 8 – Detección de Software No Autorizado

  • IT compara trimestralmente el software instalado con el F134-IT-1 (herramienta: --TODO--).
  • El software no autorizado se desinstala y se informa al responsable del área; si es malicioso, se aplica P121-IT-1.

Plazos para vulnerabilidades de seguridad: Crítica, hasta 7 días; Alta, hasta 30 días; Media y Baja, en el siguiente ciclo mensual. Si no puede cumplirse el plazo, se registra una excepción con controles compensatorios.

8 SOFTWARE DE PLANTA Y EQUIPOS CON SOPORTE LIMITADO

  • El firmware y el software de controladores CNC, PLC y robots se registran en el F134-IT-1 con versión y fabricante.
  • Antes de cada actualización se respaldan los programas y la configuración del equipo.
  • Las actualizaciones se realizan en paradas programadas y se verifican con Producción.
  • Los equipos con sistemas operativos sin soporte se aíslan de la red (segmentación según F124-IT-3), no se usan para navegar en Internet ni para correo, y solo se conectan por accesos remotos autorizados.
